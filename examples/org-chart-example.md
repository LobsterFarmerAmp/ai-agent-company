# 组织架构示例

> 以下是一个 5 人 AI Agent 公司的组织架构示例。**组织架构不由技能承载**：权威源 = `~/.openclaw/company-info/role-requirements/*.md`（岗位定义）+ 公告板；操作走 Company OS 的 `company_org_*` 工具。

## 等级体系

Boss（人类决策者）为 0 级，超脱于技能分配之外，拥有最高决策权。

| 等级 | 权限 | 成员 |
|------|------|------|
| 1 级 | 可向 2 级发布任务和指令，管理各自领域 | 首席架构师、首席技术官 |
| 2 级 | 执行任务，不发布任务，服从上级指令 | 数据工程师、后端工程师、文案策划 |

## 架构图

```
Boss（CEO）[0级]
├── 首席架构师 [1级]
│   职责：平台治理、Agent 配置管理、技能系统、定时任务
│   上级：Boss（直接汇报）
│
└── 首席技术官 [1级]
    职责：项目管理、任务分配、对外对接
    上级：Boss（直接汇报）
    │
    ├── 数据工程师 [2级]
    │   上级：首席技术官（直接主管）
    │
    ├── 后端工程师 [2级]
    │   上级：首席技术官（直接主管）
    │
    └── 文案策划 [2级]
        上级：首席技术官（直接主管）
```

## 设计要点

### 1. 管理跨度

- 每个管理者直接管理 2-3 个执行者
- 管理者也是执行者（1 级也要做实际工作）
- 避免过多的管理层级（目前只有 3 层：0 -> 1 -> 2）

### 2. 职责划分

- **首席架构师**：管平台、环境、治理规则、技能系统
- **首席技术官**：管项目、业务、任务分配、对外对接
- 两者平级，各管一摊，不互相指挥

### 3. 技能分配

技能按**来源**三分（自研 / 上游安装 / 仓内未部署），分类判据与名册见 [`../skills/README.md`](../skills/README.md)。legacy `company-*` 技能**不部署、不得引为规则出处**。

| 技能 | 类别 | 1 级 | 2 级 | 说明 |
|------|------|------|------|------|
| `persona-audit` | 自研（owned） | ✅ | ✅ | 人设审查 |
| `self-improving-agent` | 上游安装（upstream） | ✅ | ✅ | 经验记录（ClawHub 安装） |
| `coding-agent` | 上游/内置（bundled） | ✅ | ✅ | 编码委派（自愿使用） |

关键设计：
- **派发权只给 1 级**：2 级不能派活，只能执行（由 Company OS `company_task_*` 与硬规则承载，不再由技能承载）
- **执行权给所有人**：1 级也可以执行任务（自上而下或跨域协作）
- **legacy `company-*`（dialogue / org-chart / task-dispatch / task-execution / code / reporting）**：已由 Company OS 工具与 `company-hard-rules.md` 取代，**不部署**。

### 4. 通信规则

- 所有 Agent 间通信走目标 Agent 的 **main session**（单世界线原则）
- 正式任务走 Company OS 任务系统（`company_task_*`，有状态、可追踪）
- 日常沟通走 sessions_send
- 方案审阅走讨论会（`company_meeting_request` type=discussion）或 sessions_send 异步沟通

### 5. 扩展建议

- **2-3 人团队**：1 个 Boss + 1 个管理者 + 1 个执行者，去掉架构师角色
- **5-8 人团队**：保持当前结构，增加 2 级执行者
- **8+ 人团队**：考虑增加 1.5 级（team lead），但会增加通信复杂度
